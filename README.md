## `~$ Abstract`

This repository is the working record of my Cybersecurity Internship (Batch 084). It collects the weekly
projects, hands-on lab tasks, and supporting documentation completed over the programme, organised so each
week can be reviewed on its own: what the task was, how it was carried out, and the evidence that it worked.

Each week follows the same methodology: **understand → build → test → document → reflect**, with commands,
configurations, and screenshots kept alongside the write-up so every result can be reproduced.

---

## `~$ cat brief.md`

**Objective:** Build practical, evidence-backed skills in network and security fundamentals through weekly
projects and lab exercises, and document the work to a professional, portfolio-ready standard.

**Environment:** Isolated lab setups (virtual machines and sandboxed networks) built for learning. No production
systems, third-party networks, or real user data are involved.

## `~$ cat methodology.md`

- **Understand** — Read the task brief, identify the objective, and note the concepts and tools it depends on
- **Build** — Set up the lab environment and carry out the task step by step, recording every command and setting
- **Test** — Verify the outcome with a repeatable check, including a failure case where one applies
- **Document** — Write up the approach, results, and evidence in the week's README
- **Reflect** — Record what worked, what broke, and what I would do differently

## `~$ cat conventions.md`

- Every claim in a write-up is backed by evidence (screenshot, capture, or log) stored in that week's `evidence/` folder
- Work is labelled clearly as **completed**, **simulated**, or **planned**, so nothing is overstated
- Secrets, keys, tokens, and personal data are masked or regenerated before anything is committed
- Folder names follow `Week-NN`; file names are lowercase with hyphens
